3D Prompt Atlas｜使い方

← アプリへ
まずこれだけ

3ステップで使えます

  1. 何を作りたいか書く
    例：「小5向けの3D白地図ゲーム。iPadでタップ操作」
  2. 近い作例を2〜5件選ぶ
    「比較に追加」を押します。1件の丸写しではなく、複数から技法を集めます。
  3. 制作指示を生成してコピー
    必要な技法だけチェックし、「制作指示を生成」→「コピー」。Astraなどへ貼り付けます。

SCREEN GUIDE

画面の見方

何を作りたい？
目的を書く入口。短文でも構いません。
作例カード
モデル、作者、用途、技法、出典を確認できます。
比較に追加
採用候補を集めます。2〜5件が扱いやすいです。
Prompt Compiler
選んだ作例の設計原理から、実行用の指示を組み立てます。

IMPORTANT

このアプリがしないこと

  • 公開作例を「必ず同じ結果になる魔法のプロンプト」とは扱いません。
  • 第三者の画像・コード・全文を、権利確認なしに勝手に再配布しません。
  • 作者原文と、公開情報から再構成されたbriefを同じものとして扱いません。

各カードの「出典 ↗」から元ページを確認してください。GitHubコードを再利用する場合は、各リポジトリのライセンス確認が必要です。

MY PROVEN LIBRARY

うまくいったら保存

実際にAstra等で試して「この条件は効いた」と分かったら、タイトルとメモを保存します。公開作例とは別に、自分専用の成功パターンが育っていきます。

現在のMVPでは、お気に入り・成功例はこのブラウザ端末のlocalStorageに保存されます。端末を変えると自動同期されません。

WHEN SOMETHING GOES WRONG

困ったとき

  • 作例が出ない：検索語を減らすか「リセット」を押します。
  • 制作指示が生成されない：先に作例を1件以上「比較に追加」します。
  • データ読み込みエラー：HTMLを端末のファイルから直接開かず、Webサーバー上で開きます。
  • お気に入りが消えた：ブラウザデータ削除や別端末ではlocalStorageが引き継がれません。

TERMS

用語

source-derived brief：作者が公開した正確なプロンプト本文ではなく、公開情報を基に整理された制作指示。

設計原理：題材そのものではなく、「なぜその作例が成立しているか」を自分の用途へ転用できる形にした考え方。

Prompt Compiler：複数の設計原理と自分の目的をまとめ、実行用の制作指示へ組み替える機能。
